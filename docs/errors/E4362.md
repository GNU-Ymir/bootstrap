# E4362

> template specialization expected a function not <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::USE_AS_FUNCTION_TEMPLATE` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A template parameter declared `fn F` receives a function, whatever its signature:
a function or a lambda given by address, or a compile-time function pointer, such
as the tagged function an `apply {fn F}` overload of a tag receives. It was given
a type, or a value that is not a function. When it is the first parameter of an
`apply` overload, the tagged symbol is not a function, so the overload does not
apply to it.

## Example

`test_resources/tag/test93.yr`:

```ymir
fn call {fn F} ()-> __pragma!return_type (F) {
    F ()
}

fn main () {
    let _b_ = call!{12} ();
}
```

```text
Error[E4236] : undefined template call for test93::call {fn F}()-> __pragma!return_type(F) with {12}
 --> test_resources/tag/test93.yr:(26,19)
26  ┃     let _b_ = call!{12} ();
    ╋                   ^ --  error: template specialization expected a function not 12
 --> test_resources/tag/test93.yr:(20,13)
20  ┃ fn call {fn F} ()-> __pragma!return_type (F) {
    ╋             -
    ┃
    = when validating test93::main -- (test_resources/tag/test93.yr:(24,4))
    ┗━━━━━━━
```

## How to fix it

Give the address of a function, `call!{&foo} ()`. A template parameter receiving a
type is written `{T}`, and one receiving a value of a given type `{N: usize}`.
