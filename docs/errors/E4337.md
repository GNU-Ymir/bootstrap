# E4337

> <> names no function whose tags are merged into it

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::NOT_TAGGED` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

`__pragma!untagged (foo)` reaches a tagged function as written, before its tags
were merged into it, the name `foo` meaning the merged function. The name of a
function that has no tag, or whose tags merge nothing into it, already means
the function as written.

## Example

`test_resources/tag/test36.yr`:

```ymir
// __pragma!untagged only applies to a tagged function

fn foo (x: i32)-> i32 { x + 1 }

fn main () {
    let _x_ = __pragma!untagged (foo) (1);
}
```

```text
Error[E4337] : foo names no function whose tags are merged into it
 --> test_resources/tag/test36.yr:(11,34)
11  ┃     let _x_ = __pragma!untagged (foo) (1);
    ╋                                  ^^^
    ┃
    = when validating test36::main -- (test_resources/tag/test36.yr:(10,4))
    ┗━━━━━━━
```

## How to fix it

Use the name of the function directly.
