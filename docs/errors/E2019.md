# E2019

> module <> is declared neither a child nor a sibling

where `<>` stands for a value the diagnostic fills in.

Raised during **parsing**, from `SyntaxErrorMessage::MOD_WITHOUT_ROOT` (`src/ymirc/syntax/errors.yr`).

## What it means

A `mod` declaring a module defined in another file says where that file is
through the root in front of its name:

- `mod ::name;` is a **child**: `name.yr` in the directory named after the
  declaring module, `foo/name.yr` for a declaration in `foo.yr`;
- `mod .name;` is a **sibling**: `name.yr` next to the declaring file.

A `mod name;` without a root is refused. It used to look for both files, so
what it declared depended on the files present on the disk rather than on the
source.

## Example

`test_resources/diagnostics/test93.yr`:

```ymir
// a module declared neither a child nor a sibling
mod helper;

fn main () {}
```

```text
Error[E2019] : module helper is declared neither a child nor a sibling
 --> test_resources/diagnostics/test93.yr:(2,5)
 2  ┃ mod helper;
    ╋     ^^^^^^  note: write mod ::helper; for the file in the directory named after this module, or mod .helper; for the file next to this one
    ┗━━━━━━━
```

## How to fix it

Write the root of the file the module is in: `mod .helper;` for
`helper.yr` next to the declaring file, `mod ::helper;` for `test93/helper.yr`.
The submodules a `__lib__.yr` declares are next to it, so they are siblings:

```ymir
in __lib__;

pub mod .std;
pub mod .core;
```
