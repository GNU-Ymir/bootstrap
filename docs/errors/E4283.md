# E4283

> the parameter <> has a default value, it can only be passed by name

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::DEFAULT_PARAM_BY_POSITION` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A parameter that declares a default value is filled by name or left to its
default -- it is never a slot a positional argument lands in. A call that
provides one argument too many for such a prototype was written expecting the
opposite, so this hangs under the [E4212](E4212.md) arity error and names the
parameter responsible for the difference between the two counts.

It is not raised when a call is *short* of an argument: the missing parameter is
then one that has no default, and naming a defaulted one would point at the
wrong place.

A tuple cast to a record is expanded into a positional call, so it reaches this
error too. A tuple has no name syntax, so the fix there is to drop the element
and let the field take its default.

## Example

`test_resources/diagnostics/test83.yr`:

```ymir
fn foo (x : i32, y : i32 = 8)-> i32 {
    x + y
}

fn main () {
    foo (1, 2);
}
```

```text
Error[E4212] : 1 parameters is expected, but 2 are provided
 --> test_resources/diagnostics/test83.yr:(6,9)
 6  ┃     foo (1, 2);
    ╋         ^
    ┃ Error[E4283] : the parameter y has a default value, it can only be passed by name
    ┃  --> test_resources/diagnostics/test83.yr:(1,18)
    ┃  1  ┃ fn foo (x : i32, y : i32 = 8)-> i32 {
    ┃     ╋                  ^
    ┃     ┗━━━━━━━
    ┗━━━━━┻━
```

## How to fix it

Pass the parameter by name:

```ymir
foo (1, y-> 2);
```

or drop the argument and let the default apply:

```ymir
foo (1);
```
