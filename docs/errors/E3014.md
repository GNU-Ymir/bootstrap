# E3014

> module should be located in <>, but no such file exists or access is denied

where `<>` stands for a value the diagnostic fills in.

Raised during **declaration**, from `DeclareErrorMessage::NO_SUCH_FILE_ONE` (`src/ymirc/semantic/declarator/errors.yr`).

## What it means

A module was imported but the file its root names does not exist or cannot be
read: `mod ::name;` looks for `name.yr` in the directory named after the
importing module, `mod .name;` next to the importing file. The root file of a
compilation, or the `__lib__.yr` of an imported package, raises it the same way.

## Example

`test_resources/diagnostics/test95.yr`:

```ymir
// a child module with no file in the directory of the importing module
mod ::nothere;

fn main () {}
```

```text
Error[E3014] : module should be located in /bootstrap/test_resources/diagnostics/test95/nothere.yr, but no such file exists or access is denied
 --> test_resources/diagnostics/test95.yr:(2,5)
 2  ┃ mod ::nothere;
    ╋     ^^-------
    ┗━━━━━━━
```

## How to fix it

Create the file at the reported path, or fix the root of the import, a child
and a sibling being looked for in different directories. An existing file at
that path points at a permission problem instead.
