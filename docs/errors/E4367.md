# E4367

> tag <> declares apply overloads, a field cannot carry it

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::TAG_FIELD_APPLY` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A tag written on top of a field of a class or a record, `#[rename ("a-field")]`,
only registers the field: the arguments of the site are read back with
`__pragma!field_tag` or `__pragma!field_tags`, by the `apply` overload of another
tag on the type for instance. No overload is run for a field, so a tag declaring
`apply` overloads, which rewrite the symbol they are put on, cannot be put on one.

## Example

`test_resources/tag/test102.yr`:

```ymir
// A tag on a field only registers it: a tag declaring apply overloads cannot be put on a field

in test102;

tag doubled {
    pub fn apply {F: fn (i32)-> i32} (x: i32)-> i32 {
        F (x) * 2
    }

    pub record apply {record R} {}
}

tag counted {
    pub self () {}
}

record Foo {
    #[doubled, counted]
    pub let a: i32 = 0;

    pub self () {}
}

fn main () {
    let _f_ = Foo ();
}
```

```text
Error[E4367] : tag test102::doubled declares apply overloads, a field cannot carry it
 --> test_resources/tag/test102.yr:(18,7)
18  ┃     #[doubled, counted]
    ╋       ^^^^^^^
 --> test_resources/tag/test102.yr:(6,12)
 6  ┃     pub fn apply {F: fn (i32)-> i32} (x: i32)-> i32 {
    ╋            -----
   ...
10  ┃     pub record apply {record R} {}
    ╋                -----
    ┃
    = when validating test102::Foo -- (test_resources/tag/test102.yr:(17,8))
    ┗━━━━━━━
```

## How to fix it

Put the tag on the type, or declare a tag taking the same parameters and no
`apply` overload for the field, and let a tag on the type read it.
