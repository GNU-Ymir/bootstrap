# E4368

> <> carries <> sites of tag <>, where a single one was expected

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::TAG_SITE_NOT_SINGLE` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

`__pragma!tag (sym, tag)` and `__pragma!field_tag (T, "field", tag)` return the
value of the single site of `tag` written on top of a symbol or of a field: a
record holding the arguments of the site. A symbol or a field the tag is not
written on, or is written on several times, has no single site to read.

## Example

`test_resources/tag/test103.yr`:

```ymir
// __pragma!tag and __pragma!field_tag read a single site: the symbol or the field carries the tag once

in test103;

tag route (path: [c8]) {}

#[route ("/a"), route ("/b")]
fn twice () {}

fn never () {}

record Foo {
    #[route ("/x"), route ("/y")]
    pub let x: i32 = 0;

    pub let y: i32 = 0;
}

fn a () { let _x_ = __pragma!tag (twice, route); }

fn b () { let _x_ = __pragma!tag (never, route); }

fn c () { let _x_ = __pragma!field_tag (Foo, "x", route); }

fn d () { let _x_ = __pragma!field_tag (Foo, "y", route); }

fn main () {
    a ();
    b ();
    c ();
    d ();
}
```

## How to fix it

Read every site with `__pragma!tags` or `__pragma!field_tags`, which return an
array of their values, empty when there is none; or test first with
`__pragma!has_tag` or `__pragma!field_has_tag`.
