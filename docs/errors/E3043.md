# E3043

> the companion module <> is not named after a class, a record or an entity of module <>

where `<>` stands for a value the diagnostic fills in.

Raised during **declaration**, from `DeclareErrorMessage::COMPANION_WITHOUT_TYPE` (`src/ymirc/semantic/declarator/errors.yr`).

## What it means

A module declared `@companion` accesses the private and protected members of the
type it is named after, and that type must be declared in the same module as the
companion -- a class, a record or an entity, template or not. The template
parameters of either side play no part: only the name pairs them.

Here no type of the module is named `Y`, the class being `X`.

## Example

`test_resources/companion/test7.yr`:

```ymir
in test7;

class X {
    prv let _x: i32;

    pub self (x: i32)
        with _x = x
    {}
}

@companion
mod Y {
    pub fn get (x: &X)-> i32 {
        x._x
    }
}

fn main () {
    let _ : i32 = Y::get (copy X (1));
}
```

```text
Error[E3043] : the companion module Y is not named after a class, a record or an entity of module test7
 --> test_resources/companion/test7.yr:(12,5)
12  ┃ mod Y {
    ╋     ^
    ┗━━━━━━━
```

## How to fix it

Rename the module after the type it is the companion of, and declare it next to
that type. Without the `@companion` attribute, a module sees only the public
members of the types it uses.
