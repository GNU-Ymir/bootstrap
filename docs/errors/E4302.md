# E4302

> the size of a list comprehension filtered by if is not determinable at compile time

Raised during **validation**, from `ValidateErrorMessage::LIST_COMPR_FILTER_SIZE` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A comprehension filtered by `if` collects the values the filter keeps, and which
ones those are is only known once the iteration ran. Its result is therefore a
slice, appended to as the iteration goes, and a slice is allocated on the heap:
the comprehension has to be enclosed in a `copy`.

Without the filter the same comprehension has the length of the iteration, so it
can be an array on the stack, which is why dropping the `copy` is accepted
there and rejected here.

A comprehension over a tuple is the exception: its iteration is unrolled during
validation, so the filter is computed there and the length of the result is
known. It stays an array on the stack, and needs no `copy` -- at the price of a
filter that has to be a compile time value, or [E4303](E4303.md) is raised.

This is about the *number* of values, not about their type: a filter whose test
is not a boolean raises [E4095](E4095.md) instead, and a comprehension whose
iteration itself has no compile time length raises [E4109](E4109.md).

## Example

`test_resources/diagnostics/test146.yr`:

```ymir
fn main () {
    let _ = [i for i in 0 .. 10 if i != 6];
}
```

## How to fix it

Enclose the comprehension in a `copy`, as the fix of the diagnostic suggests:

```ymir
let _ = copy [i for i in 0 .. 10 if i != 6];
```
