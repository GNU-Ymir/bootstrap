# E3035

> a ctor cannot be both no_move and only_move

Raised during **declaration**, from `DeclareErrorMessage::EXCLUSIVE_MOVE_ATTRIBUTES` (`src/ymirc/semantic/declarator/errors.yr`).

## What it means

`@no_move` withdraws a ctor from the resolution of the `move` operator, and
`@only_move` restricts it to that resolution. A ctor carrying both would be
selectable from nowhere.

## Example

`test_resources/entities/test15.yr`:

```ymir
entity Foo {
    @{no_move, only_move}
    pub self () {}
}
```

```text
Error[E3035] : a ctor cannot be both no_move and only_move
 --> test_resources/entities/test15.yr:(4,16)
 4  ┃     @{no_move, only_move}
    ╋                ^^^^^^^^^
    ┗━━━━━━━
```

## How to fix it

Keep the one that says which side of the `move` operator the ctor belongs to, or
neither -- a ctor with no move attribute is a candidate on both sides.
