# E4306

> over is prohibited on a union of records

Raised during **validation**, from `ValidateErrorMessage::UNION_BASE_ON_RECORD` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A union of records is perfectly legal -- what is rejected here is the `over` on
it. `over B` states that a vtable suitable for every member already exists, so
that a method of `B` can be called on the union whichever member it holds.
Records have no vtable and no inheritance, so there is nothing for a union of
records to declare a base of. The note names the member that makes it one.

A union of records still gets the methods its members have in common: the
compiler synthesizes a table of the methods every member declares with an
identical signature, without a base being named.

## Example

`test_resources/type_union/test10.yr`:

```ymir
record A {
    let a : i32;
}

record B {
    let b : i32;
}

class Base {
    pub self () {}
}

union U over Base
| A
| B;
```

```text
Error[E4306] : over is prohibited on a union of records
 --> test_resources/type_union/test10.yr:(15,14)
15  ┃ union U over Base
    ╋              ^^^^
16  ┃ | A
    ╋   -  note: test10::A is a record type
    ┃
    = when validating test10::U -- (test_resources/type_union/test10.yr:(15,7))
    ┗━━━━━━━
```

## How to fix it

Drop the `over`, or make the members classes descending from the base.
