# E4289

> the parameters of a unit test are produced as <>, but the test takes <> parameters

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::UNITTEST_PARAMS_ARITY` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

Each element of the slice `@parameters` produces fills the parameters of one run
of the test. A test taking one parameter is fed the element itself; a test taking
several is fed a tuple of that arity, unwrapped field by field.

## Example

`test_resources/unittest/test8.yr`:

```ymir
fn params ()-> [(i32, [c8])] {
    copy [(3, "foo")]
}

@parameters (params ())
__test (len: i32, text: [c8], ratio: f64) {
    assert (len > 0 && text.len > 0us && ratio > 0.0);
}
```

```text
Error[E4289] : the parameters of a unit test are produced as (i32, [c8]), but the test takes 3 parameters
 --> test_resources/unittest/test8.yr:(6,2)
 6  ┃ @parameters (params ())
    ╋  ^^^^^^^^^^
 7  ┃ __test (len: i32, text: [c8], ratio: f64) {
    ╋         ---
    ┗━━━━━━━
```

## How to fix it

Give the tuple a field per parameter of the test, or take as many parameters as
the tuple has fields.
