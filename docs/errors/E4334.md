# E4334

> an apply overload cannot declare <>, the tagged symbol keeps its own

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::TAG_APPLY_IDENTITY` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A tag changes the shape of the declaration it is put on, never its identity.
An `apply` overload is merged into the tagged declaration, so it cannot declare
what belongs to that identity: the ancestor (`over`) and the attributes
(`@final`, `@abstract`...) of a class, the type of an enum, the base of a union.
The message quotes the element the overload declares.

## Example

`test_resources/tag/test27.yr`:

```ymir
// an apply overload cannot give an ancestor to the class it is merged into

class Base {}

tag a {
    pub class apply {class C} over Base {}
}

fn main () {}
```

```text
Error[E4334] : an apply overload cannot declare over Base, the tagged symbol keeps its own
 --> test_resources/tag/test27.yr:(6,36)
 6  ┃     pub class apply {class C} over Base {}
    ╋                                    ^^^^
    ┗━━━━━━━
```

## How to fix it

Remove the element from the `apply` overload. A tag can only be put on a class
that already has the ancestor or the attributes it needs.
