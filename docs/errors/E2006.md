# E2006

> decorator <> cannot be applied to a subpattern variable

where `<>` stands for a value the diagnostic fills in.

Raised during **parsing**, from `SyntaxErrorMessage::UNDEF_DECORATOR_IN_MATCH` (`src/ymirc/syntax/errors.yr`).

## What it means

A decorator was written on a variable of a subpattern inside a pattern match.
The subpattern variables of a match are bound by the pattern itself; they take
their mutability and their storage from the value being matched, so a decorator
on them has nothing to apply to.

## Example

`test_resources/lazyness/test14.yr`:

```ymir
class A {
    pub let x : i32 = 0;
    pub self () {}
}

fn main () {
    let lazy  A(x-> x) = lazy A();
}
```

```text
Error[E2006] : decorator lazy cannot be applied to a subpattern variable
 --> test_resources/lazyness/test14.yr:(7,9)
 7  ┃     let lazy  A(x-> x) = lazy A();
    ╋         ^^^^   ^  note: failed to read pattern variable declaration
    ┗━━━━━━━
```

## How to fix it

Remove the decorator. When the binding needs to be mutable, the decorator
belongs on the outermost variable of the pattern, not on the nested one.
