# E3011

> method <> is marked override but does not override any base method

where `<>` stands for a value the diagnostic fills in.

Raised during **declaration**, from `DeclareErrorMessage::NOT_OVERRIDE` (`src/ymirc/semantic/declarator/errors.yr`).

## What it means

A method is marked `override` but no method of an ancestor class matches it.
The marker is checked rather than trusted, so a signature that drifted from the
one it meant to override is caught here instead of silently becoming a new
method.

## How to fix it

Compare the signature with the ancestor method: parameter types, mutability
and the `self` decorators all take part in the match. If the method really is
new, drop `override`.
