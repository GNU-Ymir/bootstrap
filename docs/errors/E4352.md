# E4352

> class <> is abstract, it has no vtable

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::VTABLE_ABSTRACT_CLASS` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

`__pragma!vtable (C)` gives the address of the vtable an instance of `C` is
allocated with. An abstract class is never instantiated, its methods without a
body leave nothing to put in a vtable, so the compiler builds none for it.

## Example

`test_resources/pragma/test20.yr`:

```ymir
// __pragma!vtable on an abstract class, which has no vtable

@abstract
class Shape {
    pub self () {}

    pub fn area (self)-> i32;
}

fn main () {
    let _vt_ = __pragma!vtable (&Shape);
}
```

```text
Error[E4352] : class test20::Shape is abstract, it has no vtable
 --> test_resources/pragma/test20.yr:(11,33)
11  ┃     let _vt_ = __pragma!vtable (&Shape);
    ╋                                 ^
    ┃
    = when validating test20::main -- (test_resources/pragma/test20.yr:(10,4))
    ┗━━━━━━━
```

## How to fix it

Name a derived class that implements the empty methods: its vtable is the one an
instance would be allocated with.
