# E4352

> a value of type <> has no constructor to reset it, it is moved without arguments

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::MOVE_HANDLE_RESET` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A `move` written with arguments, `move (args) x`, or with a name, `move::name (args) x`,
calls a reset constructor of the moved entity, that rebuilds it in the variable it
leaves. A generator or an async handle has no constructor: its frame cannot be
rebuilt, so it is moved as is, and its variable cannot be used anymore (E4354).

## Example

`test_resources/movable_handles/test14.yr`:

```ymir
// a handle has no constructor to reset it after a move
yield gen (n: i32)-> i32 {
    for i in 0 .. n { yield i; }
}

fn main () {
    let g = gen (3);
    let h = move (3) g;
    for x in h {
        let _: i32 = x;
    }
}
```

```text

 --> test_resources/movable_handles/test14.yr:(8,13)
 8  ┃     let h = move (3) g;
    ╋             ^^^^     -
    ┃
    = when validating test14::main -- (test_resources/movable_handles/test14.yr:(6,4))
    ┗━━━━━━━
```

## How to fix it

Drop the arguments of the move, `move g`. To use the variable again, assign it a
new handle once it is moved.
