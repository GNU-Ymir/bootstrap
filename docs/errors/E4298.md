# E4298

> the method <> is not a value, it can only be called

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::FAKE_METHOD_CALL` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A fake method is not a field, it is a method syntax the compiler rewrites when it
is called. There is nothing to refer to before that rewriting, so the access
cannot be used as a value of its own. They are `map:.remove`, `range.stepBy`,
`range.reverse` and `generator.next`.

## Example

`test_resources/generators/test32.yr`:

```ymir
// the fake method next is not a value
yield range (i: i32, j: i32)-> i32 {
    for n in i .. j {
        yield n;
    }
}

fn main () {
    let r = range (0, 2);
    let n = r.next;
    n;
}
```

```text
Error[E4298] : the method next is not a value, it can only be called
 --> test_resources/generators/test32.yr:(10,14)
10  ┃     let n = r.next;
    ╋              ^----
    ┃
    = when validating test32::main -- (test_resources/generators/test32.yr:(8,4))
    ┗━━━━━━━
```

## How to fix it

Call the method. `r.next ()` returns the next value of the generator wrapped in
an option, `none` once the generator is over. `r:.next ()` borrows that value
mutably instead of copying it constantly, on a mutable generator yielding
borrowed data.
