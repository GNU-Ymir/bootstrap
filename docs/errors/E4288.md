# E4288

> the parameters of a unit test are produced as <>, but a generator was expected

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::UNITTEST_PROVIDER_NOT_A_GENERATOR` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

`@parameters` must produce a generator, of type `yield-> T`: the runner drains it
once, before any test runs, and registers one case per yielded parameter set,
`<test>[k]` for the `k`-th one. A slice is not accepted, whatever its elements.

The runner selects a case by its index alone, so the generator must yield the same
sets in the same order on every run for `-f "…[k]"` and `--resume` to rerun the
same case.

The attribute takes the parameter sets themselves, not a way of obtaining them, so
a generator function is called on the spot -- `@parameters (params ())`. Naming
it without calling it raises [E4084](E4084.md) instead.

## Example

`test_resources/unittest/test7.yr`:

```ymir
@parameters (copy [1, 2, 3])
__test (value: i32) {
    assert (value > 0);
}
```

```text
Error[E4288] : the parameters of a unit test are produced as mut [mut i32], but a generator was expected
 --> test_resources/unittest/test7.yr:(2,14)
 2  ┃ @parameters (copy [1, 2, 3])
    ╋              ^^^^
    ┗━━━━━━━
```

## How to fix it

Yield the parameter sets, from a generator comprehension -- `@parameters ((yield i
for i in [1, 2, 3]))`, the comprehension keeping its own parentheses -- or from a
call to a `yield` function:

```ymir
yield params ()-> i32 {
    for i in 1 ... 3 {
        yield i;
    }
}

@parameters (params ())
__test (value: i32) {
    assert (value > 0);
}
```
