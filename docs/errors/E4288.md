# E4288

> the parameters of a unit test are produced as <>, but a slice was expected

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::UNITTEST_PROVIDER_NOT_A_SLICE` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

The runner calls the frame producing the parameters once, and learns how many
times to run the test from the length of what it returns -- so `@parameters` must
produce a slice. A static array is not one: its length is part of its type, and it
is not allocated where the runner can keep it.

The attribute takes the parameter sets themselves, not a way of obtaining them, so
a function producing them is called on the spot -- `@parameters (params ())`. Naming
it without calling it raises [E4084](E4084.md) instead.

## Example

`test_resources/unittest/test7.yr`:

```ymir
@parameters ([1, 2, 3])
__test (value: i32) {
    assert (value > 0);
}
```

```text
Error[E4288] : the parameters of a unit test are produced as mut [mut i32 ; 3us], but a slice was expected
 --> test_resources/unittest/test7.yr:(2,14)
 2  ┃ @parameters ([1, 2, 3])
    ╋              ^
    ┗━━━━━━━
```

## How to fix it

Make the value a slice -- `copy [1, 2, 3]` for an array literal, or a call to a
function whose return type is a slice.
