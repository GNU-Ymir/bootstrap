# E3038

> no symbol is resolved through the use of <>

where `<>` stands for a value the diagnostic fills in.

Raised from `DeclareErrorMessage::UNUSED_USE` (`src/ymirc/semantic/declarator/errors.yr`),
by the check that runs once the whole package is validated.

## What it means

`use` does not decide what a package can reach -- package resolution and `mod`
do that, and every symbol is in the tree from the start, subject to protection.
A `use` only lets a symbol be named by its short name instead of its full path.

So this is redundant-shorthand detection, and "used" has an exact meaning: a
resolution *selected* a symbol that this `use`, and nothing else, made nameable.
Two consequences follow, and both are the rule rather than an approximation of
it:

- a candidate that lost overload resolution contributed nothing to the compiled
  program, so the `use` that offered it is still unused;
- a symbol the scope could name anyway -- written out as a full path, supplied
  by another `use`, declared in an enclosing scope, or provided by a core module
  -- was never owed to this `use` either.

## Example

`test_resources/warnings/test9.yr`, where `pick` is declared in both imported
modules and the call selects the one taking an `i32`:

```ymir
in test9;

mod ::alpha;
mod ::beta;

use test9::alpha;
use test9::beta;

fn main () {
    pick (1);
}
```

```text
Warning[E3038] : no symbol is resolved through the use of test9::beta
 --> test_resources/warnings/test9.yr:(10,12)
10  ┃ use test9::beta;
    ╋            ^^^^
    ┗━━━━━━━
```

## How to fix it

Remove the `use`. Nothing it names is reached, so nothing else changes.
