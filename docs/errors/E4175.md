# E4175

> option of type <> has no error

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::OPTION_HAS_NO_ERROR` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

The error side of an option was read on an option that never holds one.

## How to fix it

Read the value instead. An option built from a non-throwing computation has
no error, cf. [E4078](E4078.md).
