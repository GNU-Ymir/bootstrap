# E4212

> <> parameters <> expected, but <> <> provided

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::TOO_FEW_PARAMETERS` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A call provides a different number of arguments than the callee takes. Both
counts are in the message.

A parameter that declares a default value is filled by name or left to its
default, so it is not part of the count a positional call is compared against --
`foo (x: i32, y: i32 = 8)` expects one argument, not two. When the extra
arguments are explained by such a parameter, [E4283](E4283.md) hangs under this
error and names it.

## Example

`test_resources/data_record/ctors/test2.yr`:

```ymir
@data
record Foo {
    let x: i32;
}

fn main() {
    let a = Foo();
    let b = Foo(x-> 34);
    a.x;
    b.x;
}
```

```text
Error[E4212] : 1 parameters is expected, but 0 are provided
 --> test_resources/data_record/ctors/test2.yr:(7,16)
 7  ┃     let a = Foo();
    ╋                ^
    ┗━━━━━━━
```

## How to fix it

Pass the missing arguments. If the count looks right, check for a parameter with
a default value: it is reachable by name only, so it is not one of the arguments
a positional call is expected to provide.
