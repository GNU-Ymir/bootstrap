# E4356

> <> is not nogc, a nogc function cannot call it

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::NOGC_CALL` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A function marked `@nogc` never touches the heap of the garbage collector: it
is what the collector itself, and the code it calls while it runs, is written
in. It can only call the functions that make the same promise -- the ones
marked `@nogc`, and the foreign functions declared without a body, such as
`malloc` -- since any other one may allocate, and nothing checks that it does
not.

A call through a function pointer or a delegate is not checked: what it calls
is not known at compile time.

## Example

`test_resources/nogc/test2.yr`:

```ymir
// a @nogc function cannot call a function that is not @nogc

in test2;

fn helper ()-> i32 {
    1
}

@nogc
pub fn foo ()-> i32 {
    helper ()
}
```

```text
Error[E4356] : test2::helper is not nogc, a nogc function cannot call it
 --> test_resources/nogc/test2.yr:(11,12)
 9  ┃ @nogc
    ╋  ----  note: the function is nogc here
10  ┃ pub fn foo ()-> i32 {
11  ┃     helper ()
    ╋            ^
    ┃
    = when validating test2::foo -- (test_resources/nogc/test2.yr:(10,8))
    ┗━━━━━━━
```

## How to fix it

Mark the called function `@nogc` if it never allocates on the GC heap, or do
not call it from a `@nogc` function.
