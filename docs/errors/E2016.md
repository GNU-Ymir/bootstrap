# E2016

> the value of the previous arm was read as the operand of the operator <>

Raised during **parsing**, from `SyntaxErrorMessage::ARM_READ_AS_OPERAND` (`src/ymirc/syntax/errors.yr`).

## What it means

Nothing ends an arm whose value is a simple expression, so when the pattern of
the next arm opens with a `(` or a `[`, it is read as the argument list of a call,
or an index, applied to that value. The parser then meets the `=>` (or the `if` of
a guard) of the next arm where it expected a pattern.

## Example

`test_resources/diagnostics/test150.yr`:

```ymir
fn describe (day: i32, month: i32)-> [c8] {
    match (day, month) {
        (25, 12) => "Christmas"
        (1, 1) => "New Year's Day"
        _ => "an ordinary day"
    }
}

fn main () {
    let _d_ = describe (25, 12);
}
```

```text
Error[E2016] : the value of the previous arm was read as the operand of the operator ()
 --> test_resources/diagnostics/test150.yr:(5,16)
 5  ┃         (1, 1) => "New Year's Day"
    ╋         -      ^^  note: the pattern of the arm was read as its arguments, end the previous arm with a comma or put its value in braces
    ┗━━━━━━━
```

## How to fix it

End the previous arm with a comma, `(25, 12) => "Christmas",`, or put its value
in braces, `(25, 12) => { "Christmas" }`. A `;` is not a fix: it makes the arm a
statement, whose value is `void`.
