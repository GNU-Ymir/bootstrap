# E4339

> <> names no single function, class, enum or union to carry tags

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::NOT_TAGGABLE` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

`__pragma!has_tag (sym, tag)` tells whether `tag` is written on top of the
declaration of `sym`. Tags are only written on top of a function, a class, a
record, an enum or a union, or a template of one of them, so `sym` must name
exactly one such symbol: a type that is none of them, a variable, or an
overload set of several functions has no tags to look at.

## Example

`test_resources/tag/test66.yr`:

```ymir
// __pragma!has_tag applies to a single function, class, enum or union

tag a {}

#[a]
fn foo (x: i32)-> i32 { x }

#[a]
fn foo (x: f32)-> f32 { x }

fn main () {
    let x = 1;
    let _a_ = __pragma!has_tag (i32, a);
    let _b_ = __pragma!has_tag (x, a);
    let _c_ = __pragma!has_tag (foo, a);
}
```


## How to fix it

Name the declaration the tag is written on top of. To ask about one function of
an overload set, give the functions distinct names.
