# E4155

> <> is a map access, and cannot be used as a lvalue

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::NOT_A_LVALUE_MAP_ACCESS` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A map access was used as an lvalue. A map lookup produces the value stored, not
the slot it lives in, so writing to it would not reach the map.

## Example

`test_resources/lit_map/test10.yr`:

```ymir
fn main () {
    let dmut a : [[c8] => [i32]] = copy [];

    a ["foo"] = copy [0];
    if let Ok (ref dmut z) = ref a ["foo"] {
        z ~= [8];
    }
}
```

```text
Error[E4155] : a ["foo"s8] is a map access, and cannot be used as a lvalue
 --> test_resources/lit_map/test10.yr:(5,30)
 5  ┃     if let Ok (ref dmut z) = ref a ["foo"] {
    ╋                              ^^^   ^
    ┗━━━━━━━
```

## How to fix it

Use the map's insertion operation to write, rather than assigning to the
lookup.
