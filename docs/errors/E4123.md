# E4123

> the pattern matching has no default case, so each branch must produce a void value not a <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::MATCH_NOT_COMPLETE` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A pattern matching used as an expression has no default case, so a value not
covered by any pattern would have nothing to produce.

## Example

`test_resources/diagnostics/test52.yr`:

```ymir
fn main () {
    let x = 1;
    let _ = match x {
        1 => { 2 }
    };
}
```

```text
Error[E4123] : the pattern matching has no default case, so each branch must produce a void value not a i32
 --> test_resources/diagnostics/test52.yr:(4,14)
 4  ┃         1 => { 2 }
    ╋              ^
    ┃
    = when validating pattern matching with value #_value of type i32 -- (test_resources/diagnostics/test52.yr:(3,13))
    = when validating test52::main -- (test_resources/diagnostics/test52.yr:(1,4))
    ┗━━━━━━━
```

## How to fix it

Add a default case producing a value of the same type, or make the match a
statement by having its branches produce nothing.

A match over a sealed type -- a union or an enum -- is not reported here: it
must cover the type whatever its arms produce, and is reported by
[E4318](E4318.md) instead.
