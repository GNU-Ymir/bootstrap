# E4371

> enum <> has no field named <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::UNDEFINED_ENUM_NAME` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

`E::__valueOf__ (name)` returns the field of the enum `E` named `name`, wrapped
in an option. When the name is known at compile time, the call is replaced by
the field itself, so a name naming no field of the enum is rejected there
instead of producing `none` at run time. The fields a tag appends to the enum
are fields like the others.

## Example

`test_resources/enumeration/test38.yr`:

```ymir
// A name known at compile time naming no field of the enum is an error.

enum Color
| RED = 0
| GREEN = 1;

fn main () {
    let _ = Color::__valueOf__ ("BLUE");
}
```

```text
Error[E4371] : enum test38::Color has no field named BLUE
 --> test_resources/enumeration/test38.yr:(8,33)
 8  ┃     let _ = Color::__valueOf__ ("BLUE");
    ╋                                 ^
    ┃
    = when validating test38::main -- (test_resources/enumeration/test38.yr:(7,4))
    ┗━━━━━━━
```

## How to fix it

Name one of the fields of the enum, `E::__names__` holding all of them. A name
known only at run time is looked up when the program runs, and the call returns
`none` when it names no field.
