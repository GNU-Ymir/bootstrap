# E4336

> <> is used before its tags are merged into it

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::TAG_MERGE_CYCLE` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

The name of a tagged function means the instance of the `apply` overload its
tags merged into it. That instance is made from the prototype of the function
as written, which is validated first: anything this prototype needs, the
arguments of its tags included, cannot use the name of the function, whose
merge is not done yet.

## Example

`test_resources/tag/test38.yr`:

```ymir
// the prototype of a tagged function is validated before its tags are merged into it

tag doubled {
    pub fn apply {F: fn (i32)-> i32} (x: i32)-> i32 {
        F (x) * 2
    }
}

#[doubled]
fn foo (x: i32)-> typeof (foo (x)) { x }

fn main () {
    let _x_ = foo (1);
}
```

```text
Error[E4336] : test38::foo is used before its tags are merged into it
 --> test_resources/tag/test38.yr:(15,27)
15  ┃ fn foo (x: i32)-> typeof (foo (x)) { x }
    ╋    ---                    ^^^  note: defined here
    ┃
    = when validating test38::foo -- (test_resources/tag/test38.yr:(15,4))
    = when validating test38::foo -- (test_resources/tag/test38.yr:(15,4))
    ┗━━━━━━━
```

## How to fix it

Write the type the function returns instead of computing it from a call of the
function. The body of the function is validated once the merge is done, so it
can use its name, which then means the merged function.
