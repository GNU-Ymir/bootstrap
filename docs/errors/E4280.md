# E4280

> <> called with <> works with multiple candidates

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::WORKS_WITH_BOTH` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A call matches several candidates equally well, so overload resolution has no
single answer. The candidates are listed under the diagnostic.

## Example

`test_resources/root_path/test7.yr`:

```ymir
mod A {
    pub fn foo ()-> i32 { 12 }
}

mod B {
    mod A {
        pub fn foo ()-> f64 { 12.0 }
    }

    pub fn bar ()-> f64 {
        A::foo ()
    }
}

fn main () {
    let a = B::bar ();
    a;
}
```

```text
Error[E4280] : foo called with {} works with multiple candidates
 --> test_resources/root_path/test7.yr:(11,16)
11  ┃         A::foo ()
    ╋                ^  note: candidate test7::A::foo ()-> i32 -- (test_resources/root_path/test7.yr:(2,12))
    ┃                ┗━ note: candidate test7::B::A::foo ()-> f64 -- (test_resources/root_path/test7.yr:(7,16))
    ┗━━━━━━━
```

## How to fix it

Make the call select one: convert an argument explicitly, pass an argument by
name, or qualify the symbol with its module.
