# E4135

> expression refers to multiple symbols that generate types

Raised during **validation**, from `ValidateErrorMessage::MULTIPLE_SYMBOL_TYPES` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A name resolves to several symbols that all denote types, so the expression has
no single type to mean.

## Example

`test_resources/diagnostics/test114.yr`:

```ymir
// a type name brought by two imported modules
mod first {
    pub class Point {
        pub self () {}
    }
}

mod second {
    pub class Point {
        pub self () {}
    }
}

use first;
use second;

fn main () {
    let _p_ : &Point = copy first::Point ();
}
```

```text

 --> test_resources/diagnostics/test114.yr:(18,16)

    ╋                ^^^^^
 --> test_resources/diagnostics/test114.yr:(3,15)
 3  ┃     pub class Point {
    ╋               -----  note: candidate test114::first::Point
   ...
 9  ┃     pub class Point {
    ╋               -----  note: candidate test114::second::Point
    ┃
    = when validating test114::main -- (test_resources/diagnostics/test114.yr:(17,4))
    ┗━━━━━━━
```

## How to fix it

Qualify the name with the module it should come from, or remove the import
that brings in the other one.
