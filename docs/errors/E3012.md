# E3012

> no module named <> found inside module <>

where `<>` stands for a value the diagnostic fills in.

Raised during **declaration**, from `DeclareErrorMessage::NO_MODULE_NAMED` (`src/ymirc/semantic/declarator/errors.yr`).

## What it means

A `use` names a module that does not exist inside the module it was looked up
in. Both names are reported.

## How to fix it

Check the spelling and the path of the import. A module that exists on disk
but is not reachable this way is usually a package-root problem: the include
path has to contain the directory the package root sits in.
