# E4333

> <> is <>, but the overload receiving it is declared as <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::TAG_APPLY_KIND` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

An `apply` overload of a tag is merged into the declaration it tags, so it is
declared with the same kind: a function overload is merged into a function, a
class overload into a class, an enum overload into an enum... Its first
template parameter receives the tagged declaration, but the overload is
declared with another kind.

It is reported as a candidate of [E4332](E4332.md), when no other overload of
the tag applies to the declaration.

## Example

`test_resources/tag/test24.yr`:

```ymir
// an apply overload receiving a class is declared as a class

tag a {
    pub fn apply {class C} ()-> i32 { 1 }
}

#[a]
class Foo {}

fn main () {}
```

```text
Error[E4332] : tag test24::a does not apply to class test24::Foo
 --> test_resources/tag/test24.yr:(7,3)
 7  ┃ #[a]
    ╋   ^
 --> test_resources/tag/test24.yr:(4,12)
 4  ┃     pub fn apply {class C} ()-> i32 { 1 }
    ╋            -----  note: candidate function test24::a::apply {class C}
    ┃                ┗━ error: test24::Foo is a class, but the overload receiving it is declared as a function
    ┃
    = when validating test24::Foo -- (test_resources/tag/test24.yr:(8,7))
    ┗━━━━━━━
```

## How to fix it

Declare the overload with the kind of the declarations it receives, here
`pub class apply {class C} { ... }`.
