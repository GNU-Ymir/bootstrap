# E2015

> attribute <> takes <> argument(s), but <> were given

where `<>` stands for a value the diagnostic fills in.

Raised during **parsing**, from `SyntaxErrorMessage::ATTRIBUTE_ARITY` (`src/ymirc/syntax/errors.yr`).

## What it means

An attribute taking arguments takes a fixed number of them, and was written with
a different number -- or, as below, with none at all.

## Example

`test_resources/diagnostics/test92.yr`:

```ymir
@parameters
__test (value: i32) {
    assert (value > 0);
}
```

```text
Error[E2015] : attribute parameters takes 1 argument(s), but 0 were given
 --> test_resources/diagnostics/test92.yr:(2,2)
 2  ┃ @parameters
    ╋  ^^^^^^^^^^
    ┗━━━━━━━
```

## How to fix it

Give the attribute the arguments it takes. `@parameters` takes the one value
producing the parameter sets of the test.
