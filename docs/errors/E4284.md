# E4284

> the parameter <> can only be passed by name

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::NAMED_PARAM_BY_POSITION` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A parameter marked `@` is forced named: a call fills it by name, in any position
relative to the positional arguments, and never by position. A call that leaves
it unnamed is rejected, one error per such parameter, each pointing at the
parameter's declaration.

When the positional arguments are otherwise the right number, this is the only
reason the call fails. When they are not, it comes with the
[E4212](E4212.md) arity error it explains: the positional values that were
written for the marked parameters are the ones counted too many or too few.

The call is rejected as a candidate, so these errors are listed under the
candidate note of [E4226](E4226.md).

## Example

`test_resources/diagnostics/test145.yr`:

```ymir
fn foo (@a: i32, b: i32)-> i32 { a + b }

fn main () { foo (1); }
```

```text
Error[E4226] : the call operator is not defined for test145::foo (@a: i32, b: i32)-> i32 and {1: i32}
 --> test_resources/diagnostics/test145.yr:(3,18)
 1  ┃ fn foo (@a: i32, b: i32)-> i32 { a + b }
    ╋    ---  note: candidate test145::foo (@a: i32, b: i32)-> i32
    ┃      ┗━ error: the parameter a can only be passed by name
 2  ┃
 3  ┃ fn main () { foo (1); }
    ╋                  ^
    ┃
    = when validating test145::main -- (test_resources/diagnostics/test145.yr:(3,4))
    ┗━━━━━━━
```

## How to fix it

Name the parameter at the call site:

```ymir
foo (a-> 1, 2);
```
