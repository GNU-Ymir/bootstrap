# E4353

> a value of type <> can only be moved out of the local variable or the parameter owning it

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::MOVE_HANDLE_NOT_OWNED` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A generator or an async handle has one owner, and a move gives it away for good:
the compiler checks that the variable it leaves is not used anymore (E4354). That
is only known of a local variable or a by-value parameter of the current function.
A field, an element, a dereferenced pointer or a `ref` parameter belongs to a value
the compiler does not follow, so a handle cannot be moved out of it, which would
leave its owner with a handle it does not own anymore.

## Example

`test_resources/movable_handles/test13.yr`:

```ymir
// a handle can only be moved out of the variable owning it, not out of a field
yield gen (n: i32)-> i32 {
    for i in 0 .. n { yield i; }
}

entity Holder {
    pub let handle: yield-> i32;

    pub self (h: yield-> i32) with handle = move h {}
}

fn main () {
    let mut holder = Holder (gen (3));
    let g = move holder.handle;
    for x in g {
        let _: i32 = x;
    }
}
```

```text
 --> test_resources/movable_handles/test13.yr:(14,13)
14  ┃     let g = move holder.handle;

```

## How to fix it

Borrow the handle where it is stored, a `for` loop, an `await`, a `run` or a
`poll` leaving it owned by its field. To give it away, keep it in a local variable
until then.
