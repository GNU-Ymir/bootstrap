# E4313

> union <> cannot be converted to <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::UNION_NARROWING` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

Conversion into a union is one way. A member widens into the union listing it
wherever a conversion is allowed -- a variable initialization, an assignment, an
argument, a returned value -- and the widening records which member it is, as
the tag the union object carries.

Going back is not a conversion. The member held is only known at runtime, so
recovering it is a test, and a test is what a pattern is: naming a member binds
it with its own type when the tag says the union holds it, whether the pattern
is written as an arm of a `match` or as an `if let`. Nothing about a union value
says statically which member it is, so no conversion can produce one.

The base a union declares is no exception. `union U over B` says every member
descends from `B`, which is what lets the methods of `B` be called on the union
directly; it does not make the union an instance of `B`. The union object is
its own aggregate -- a tag, a vtable and the overlay of the members -- and the
`&B` is inside that overlay, reached the same way as any other member.

## Example

`test_resources/type_union/test37.yr`:

```ymir
class A {
    pub self () {}
}

class B {
    pub self () {}
}

union U
| A
| B;

fn take (u : &U)-> &A {
    u
}
```

```text

```

## How to fix it

Name the member in a pattern -- an arm of a `match` over the union, or an
`if let` -- and work there, which is where the member has its own type.
