# E4372

> tag <> declares apply overloads, a method cannot carry it

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::TAG_METHOD_APPLY` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A tag written on top of a method of a class, a record or an entity,
`#[slot ("open")]`, only registers the method, as a tag on a field registers
the field (cf. [E4367](E4367.md)): the arguments of the site are read back with
`__pragma!method_tag` or `__pragma!method_tags`, by the `apply` overload of a
tag on the type for instance. No overload is run for a method, so a tag
declaring `apply` overloads, which rewrite the symbol they are put on, cannot
be put on one.

## Example

`test_resources/tag/test113.yr`:

```ymir
// A tag on a method only registers it: its path names a tag declaring no apply overload, and its arguments bind the parameters of the tag

in test113;

tag doubled {
    pub fn apply {F: fn (i32)-> i32} (x: i32)-> i32 {
        F (x) * 2
    }

    pub class apply {class C} {}
}

tag slot (signal: [c8], n: i32 = 1) {}

lazy NAME: [c8] = "c";

fn notATag () {}

class Foo {
    pub self () {}

    #[doubled]
    pub fn a (self, x: i32)-> i32 { x }

    #[slot (1)]
    pub fn b (self) {}

    #[slot (NAME)]
    pub fn c (self) {}

    #[slot ("d", m-> 2), notATag]
    pub fn d (self) {}
}

fn main () {
    let _f_ = Foo ();
}
```

## How to fix it

Put the tag on the type, or declare a tag taking the same parameters and no
`apply` overload for the method, and let a tag on the type read it.
