# E4360

> parameter access out of bound(<>), the arity of the function is <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::PARAMETER_ARITY_OVERFLOW` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

`__pragma!parameter_type (F, i)` selects the parameter at index `i`, counted from
zero, the `self` of a method not being a parameter. The index is negative, or not
below the number of parameters of the function, both given in the message.

## Example

`test_resources/pragma/test29.yr`:

```ymir
fn foo (x: i32, y: [c8])-> i32 {
    x + cast!i32 (y.len)
}

fn main () {
    let _a_: __pragma!parameter_type (foo, 2us) = 1;
}
```

```text
Error[E4360] : parameter access out of bound(2), the arity of the function is 2
 --> test_resources/pragma/test29.yr:(14,44)
14  ┃     let _a_: __pragma!parameter_type (foo, 2us) = 1;
    ╋                                            ^
    ┃
    = when validating test29::main -- (test_resources/pragma/test29.yr:(13,4))
    ┗━━━━━━━
```

## How to fix it

Correct the index; parameters are numbered from zero.
