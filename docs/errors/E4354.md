# E4354

> the value <> of type <> cannot be the value of a template parameter

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::TEMPLATE_VALUE_NOT_MANGLEABLE` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

The value of a template parameter, or of the parameter of a tag, is part of the
name of every symbol instantiated from it, so two instances binding different
values never share a symbol. A compile-time value is accepted only when that
name can be built from it: a scalar, a string, and a tuple, an array, a range,
an option or a structure literal made of such values, an enum field, a null
pointer or a function. A value holding a slice that is not a string, such as
the type info of a type, has no such name.

## Example

`test_resources/tag/test82.yr`:

```ymir
// The type info of a type holds a slice, which has no mangling, it cannot be the argument of a tag

in test82;

use core::types::info;

tag t (info: TypeInfo) {
    pub self {class C} () {}
}

#[t (i32::typeinfo)]
class A {
    pub self () {}
}

fn main () {}
```

## How to fix it

Pass the parts of the value that are needed, such as the name or the size of
the type info, or pass the type itself as a type parameter.
