# E4305

> __pragma <> is not enclosed in a <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::NO_ENCLOSING_PRAGMA` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

`__pragma!module`, `__pragma!function` and `__pragma!decl` name the symbol they
are written inside of. Each walks the symbols enclosing the pragma outwards
until it meets the kind it names -- a module, a function, or a class, record,
entity, trait, enum or union -- and raises this error when it reaches the top
without finding one.

`__pragma!decl` is the one that usually raises it: a pragma written in a plain
function of a module is enclosed in no declaration at all. `__pragma!function`
raises it wherever an expression is validated outside any frame, such as the
value of an enumeration member.

`__pragma!file` and `__pragma!line` read the location of the pragma itself, and
never raise it.

## Example

`test_resources/diagnostics/test149.yr`:

```ymir
fn main () {
    let _x_ = __pragma!decl ();
}
```

```text
Error[E4305] : __pragma decl is not enclosed in a declaration
 --> test_resources/diagnostics/test149.yr:(2,15)
 2  ┃     let _x_ = __pragma!decl ();
    ╋               ^^^^^^^^
    ┃
    = when validating test149::main -- (test_resources/diagnostics/test149.yr:(1,4))
    ┗━━━━━━━
```

## How to fix it

Move the pragma inside the kind of symbol it names, or use one that is always
available at that point:

```ymir
class A {
    pub self () {}

    pub fn foo (self) {
        let _x_ = __pragma!decl ();     // "main::A"
        let _y_ = __pragma!function (); // "main::A::foo"
        let _z_ = __pragma!module ();   // "main"
    }
}
```
