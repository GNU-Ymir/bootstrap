# E4084

> cannot create a function pointer from <> implicitly

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::IMPLICIT_ADDRESS_FUNCTION` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A function was used where a function pointer is expected, without asking for
its address. Ymir does not take the address of a function implicitly, so a
function name used as a value is a mistake rather than a conversion.

## Example

`test_resources/diagnostics/test39.yr`:

```ymir
fn foo ()-> i32 { 0 }

fn main () {
    let _: fn ()-> i32 = foo;
}
```

```text
Error[E4084] : cannot create a function pointer from test39::foo ()-> i32 implicitly
 --> test_resources/diagnostics/test39.yr:(1,4)
 1  ┃ fn foo ()-> i32 { 0 }
    ╋    ^^^
   ...
 --> test_resources/diagnostics/test39.yr:(4,26)
 4  ┃     let _: fn ()-> i32 = foo;
    ╋                          ^^^  note: did you forget ()?
    ┃                            ┗━ note: or did you forget &?
    ┗━━━━━━━
```

## How to fix it

Write `&` before the function name.
