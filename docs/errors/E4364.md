# E4364

> the compile-time execution throws an exception of type <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::CTE_EXEC_EXCEPTION` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A value needed at compile time calls a function, which the compiler executed to
compute the value, and the execution threw an exception that nothing caught. The
note points at the `throw` that raised it. At run time the same call would throw
the same exception.

## Example

`test_resources/cte_exec/test2.yr`:

```ymir
fn overflow () {
    let _ = cte ("256").to!{u8} ();
}
```

```text
Error[E4364] : the compile-time execution throws an exception of type std::conv::errors::CastFailure
 --> test_resources/cte_exec/test2.yr:(7,33)
 7  ┃     let _ = cte ("256").to!{u8} ();
    ╋                                 ^
 --> std/conv.yr:(1020,17)
1020 ┃                 throw copy CastFailure(T::typeinfo, [U]::typeinfo);
     ╋                 -----  note: here
     ┃
     = when validating test2::overflow -- (test_resources/cte_exec/test2.yr:(6,4))
     ┗━━━━━━━
```

## How to fix it

Give the call arguments it accepts, `("255").to!{u8} ()`, or catch the exception
inside the executed function and return a value instead.
