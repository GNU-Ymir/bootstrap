# E4370

> version <> has no value

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::VERSION_NO_VALUE` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A version can be given a value on the command line, `-fversion=FOO=12`, read as
a string by `__pragma!version_value(FOO)`. The version it reads is either not
set, or set without a value (`-fversion=FOO`, or a `-fversion=FOO=12` followed
by a `-fversion=FOO`, the last one given winning).

## Example

`test_resources/version/test5.yr`, compiled with `-fversion=BARE`:

```ymir
fn bare () {
    let _ = __pragma!version_value(BARE);
}
```

```text
Error[E4370] : version BARE has no value
 --> test_resources/version/test5.yr:(9,36)
 9  ┃     let _ = __pragma!version_value(BARE);
    ╋                                    ^^^^
    ┃
    = when validating test5::bare -- (test_resources/version/test5.yr:(8,4))
    ┗━━━━━━━
```

## How to fix it

Give the version a value (`-fversion=BARE=12`). A version that may not be set is
read under `__pragma!has_version`, the untaken branch of a `cte if` being never
validated; it does not tell a version set without a value apart, which still
raises the error:

```ymir
let x = cte if __pragma!has_version(LEVEL) {
    cte to!{i32}(__pragma!version_value(LEVEL))
} else {
    0
};
```
