# E4315

> <> is not a union type

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::NOT_A_UNION` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A template parameter written `union T` constrains the kind of type that may be
bound to it, the way `class T` or `tuple T` do: it accepts a union and nothing
else. The constraint is checked wherever the argument comes from -- written
explicitly at the call site, or deduced from a parameter typed `T`.

What fails is the candidate, not the program: a template whose parameter cannot
be bound is discarded, so this diagnostic is reported as the reason under the
error naming the call, and the call fails only when no candidate is left.

## Example

`test_resources/type_union/test62.yr`:

```ymir
fn keep {union T} (u : T)-> T {
    u
}

fn main () {
    keep (12);
}
```

## How to fix it

Pass a union, or drop the `union` constraint when the parameter is meant to
accept any type.
