# E4285

> parameter with a default value cannot be marked <>, it can already only be passed by name

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::NAMED_PARAM_WITH_DEFAULT` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

The `@` marker forces a parameter to be passed by name. A parameter that declares
a default value is already filled by name or left to its default, never by
position (cf. [E4283](E4283.md)), so the marker has nothing left to ask and the
two cannot be combined. The error points at the parameter and at its default
value.

## Example

`test_resources/diagnostics/test84.yr`:

```ymir
fn foo (@a: i32 = 2)-> i32 { a }

fn main () { foo (); }
```

## How to fix it

Drop the marker, the parameter stays passed by name:

```ymir
fn foo (a: i32 = 2)-> i32 { a }
```

or drop the default value, if the parameter has to be provided at every call.
