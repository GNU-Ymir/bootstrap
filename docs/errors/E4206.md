# E4206

> the function <> might throw an exception of type <>, but that is not declared in its prototype

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::THROWS_NOT_DECLARED` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A function can throw an exception its prototype does not declare. Ymir checks
that the throw list of a function covers everything its body can raise.

## Example

`test_resources/lit_class/ctors/test7.yr`:

```ymir
fn foo (t : bool = false)-> i32
    throws AssertError
{
    assert (t);
    12
}

record A {
    let a : i32 = 0;

    pub self ()
        with a = foo ()
    {}

}
```

```text
Error[E4206] : the function test7::A::self might throw an exception of type core::exception::assertion::AssertError, but that is not declared in its prototype
 --> test_resources/lit_class/ctors/test7.yr:(11,9)
11  ┃     pub self ()
    ╋         ^^^^
    ┃ Note :
    ┃  --> test_resources/lit_class/ctors/test7.yr:(12,22)
    ┃ 12  ┃         with a = foo ()
    ┃     ╋                      ^
    ┃     ┗━━━━━━━
    ┗━━━━━┻━
```

## How to fix it

Add the exception to the `throws` clause, or catch it inside the function.
