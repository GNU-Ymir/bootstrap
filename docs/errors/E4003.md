# E4003

> exception type <> is already caught by another catching pattern of type <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::ALREADY_CAUGHT` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

Two catch patterns of the same `try` catch the same exception type, and the
second can never run because the first already covers it.

## How to fix it

Remove the redundant pattern, or reorder them so the more specific type comes
first: a pattern catching a base class shadows every pattern for a derived one
written after it.
