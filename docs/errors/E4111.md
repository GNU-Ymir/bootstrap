# E4111

> macro call with "<>" does not match the rule "<>"

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::MACRO_DOES_NOT_MATCH` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A macro call does not match the rule it was tried against. Both the call and
the rule are quoted in the message.

## Example

`test_resources/lit_macro/test21.yr`:

```ymir
/*
 * A macro call matching none of the branches of a '|' operator
 */

macro alt {
    self (v=(a=__literal | b=__ident) ";") skips (" ") #{
        #(v)
    }
}

fn foo ()-> i32 {
    alt#{ + ; }
}
```

## How to fix it

Compare the call with the rule. When a macro has several rules, each one that
was tried is reported, so the diagnostic shows why none matched.
