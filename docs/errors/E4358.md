# E4358

> the parameters of <> are not known, __pragma <> reflects over an instantiated function

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::PRAGMA_UNINSTANTIATED` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A function template, or a lambda whose parameters are not typed, has no signature
until its template parameters are known: the types of its parameters and its return
type depend on them, so a reflection pragma has nothing to describe.

## Example

`test_resources/pragma/test30.yr`:

```ymir
fn tmpl {T} (x: T)-> T { x }

fn main () {
    let _b_: __pragma!return_type (tmpl) = 1;
}
```

```text
Error[E4358] : the parameters of test30::tmpl{T} are not known, __pragma return_type reflects over an instantiated function
 --> test_resources/pragma/test30.yr:(20,36)
20  ┃     let _b_: __pragma!return_type (tmpl) = 1;
    ╋                                    ^^^^
    ┃
    = when validating test30::main -- (test_resources/pragma/test30.yr:(18,4))
    ┗━━━━━━━
```

## How to fix it

Instantiate the template first, `__pragma!return_type (tmpl!{i32})`, or give the
parameters of the lambda a type.
