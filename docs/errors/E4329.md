# E4329

> the variable <> is declared mutable but never mutated

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::DECLARED_MUT_NOT_MUTATED` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A local variable was declared `mut` or `dmut`, but nothing ever mutates it: it
is never rebound, none of its elements is written, and it is never handed out
by `alias`, `ref`, `&` or `move`. Mutability is a permission the declaration
grants, and one granted for nothing hides the variables that really change.

A single reachable mutation is enough, even in one branch only. A parameter is
never reported, its mutability being part of the signature, and neither is a
variable initialized by a literal, that `mut` keeps from being folded at
compile time.

## Example

`test_resources/warnings/test36.yr`:

```ymir
fn main () {
    let dmut c = copy [1, 2, 3];
    c;
}
```

```text
Warning[E4329] : the variable c is declared mutable but never mutated
 --> test_resources/warnings/test36.yr:(11,9)
11  ┃     let dmut c = copy [1, 2, 3];
    ╋         ^^^^
    ┗━━━━━━━
```

## How to fix it

Remove the decorator. When the type of the variable is written with inner
mutable levels (`let mut a : [mut i32]`), remove them as well.
