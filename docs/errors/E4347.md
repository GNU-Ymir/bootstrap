# E4347

> cannot await a value of type <> through its method poll

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::AWAIT_POLL` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

Awaiting a class calls its method `poll` with the waker of the current async,
`poll (waker: dg ()-> void)-> U?`, and the await is typed `U`. The method is
found by name, as a `for` loop finds `begin`, `end` and `next`, and the class is
evaluated once, before the first poll. This error wraps the reason the method
could not be called that way: the class has no `poll`, its parameters do not
take the waker, it does not return an option ([E4348](E4348.md)), it throws
([E4349](E4349.md)), or it is mutable and the class is not awaited by
`await alias c`.

The method follows a contract the compiler cannot check:

- an option holding a value completes the await, with that value;
- an option without a value means pending: the async gives control back to its
  driver, and `poll` is called again the next time it is resumed;
- before returning pending, `poll` must arrange for the waker to be called,
  from any thread, once a new poll can progress. A `poll` that never calls it
  leaves the async suspended forever, since its driver only resumes it when it
  is woken.

## Example

`test_resources/async/test44.yr`:

```ymir
// The method poll of an awaited class takes the waker, a dg ()-> void.

class NoWaker {
    pub self () {}

    pub fn poll (self)-> i32? {
        none
    }
}

async outer ()-> i32 {
    await copy NoWaker ()
}
```

## How to fix it

Declare `poll` as `fn poll (self, waker: dg ()-> void)-> U?`, or with `mut self`
and await the class by `await alias c`.
