# E4374

> the destructor of <> is not nogc, a nogc function cannot run it

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::NOGC_DTOR` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A function marked `@nogc` runs the destructor of every entity it owns, without
calling it explicitly: the result of a call, the value a `move` gives it, a
parameter taken by value, all destroyed when the frame leaves their scope. Such
a destructor is called from the `@nogc` frame, so it must make the same promise
and be marked `@nogc`. So must the destructors of the fields a `@nogc`
destructor destroys.

The destructor an entity gets to destroy its fields, when it declares none, is
`@nogc` when theirs all are.

## Example

`test_resources/nogc/test8.yr`:

```ymir
// a @nogc function cannot run a destructor that is not @nogc, the one of an entity it constructs

in test8;

extern (C) fn printf (c: *c8, ...);

entity A {
    @nogc
    pub self () {}

    __dtor (mut self) {
        let x = copy [1, 2, 3];
        printf ("dtor allocated %d ints on the GC heap\n".ptr, cast!{i32} (x.len));
    }
}

@nogc
pub fn run () {
    let _ = A ();
}
```

## How to fix it

Mark the destructor `@nogc`, and remove from it what allocates on the GC heap,
or do not own the entity in a `@nogc` function.
