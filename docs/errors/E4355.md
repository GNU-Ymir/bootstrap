# E4355

> <> is moved out inside a loop, but declared outside of it, so the next iteration would use it again

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::MOVE_IN_LOOP` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A generator or an async handle moved out of its variable inside a loop would be
moved again by the next iteration, which no longer finds it there. The move is only
accepted when the variable is assigned by the very statement moving it,
`g = adapt (move g)`, which gives it a new handle for the next iteration.

## Example

`test_resources/movable_handles/test12.yr`:

```ymir
// a generator declared outside a loop cannot be moved inside it, the next iteration
// would move it again
yield gen (n: i32)-> i32 {
    for i in 0 .. n { yield i; }
}

fn consume (g: yield-> i32) {
    for x in g {
        let _: i32 = x;
    }
}

fn main () {
    let g = gen (3);
    for _ in 0 .. 2 {
        consume (move g);
    }
}
```

```text
 --> test_resources/movable_handles/test12.yr:(16,23)

```

## How to fix it

Declare the variable inside the loop, move it after the loop, or replace it in the
statement moving it, `g = adapt (move g)`.
