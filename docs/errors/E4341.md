# E4341

> an async cannot throw exceptions, it returns its errors in an option

Raised during **validation**, from `ValidateErrorMessage::ASYNC_THROWS` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

An async is resumed by whoever drives it, `run` or an `await`, long after the
call that created it, so the exceptions it declares could not be tracked. An
async never throws: like a delegate, it reports an error through the value it
completes with. An async method, declared by `async` in a class, a record or a
trait, is rejected the same way, and so is an async lambda (`async |x| { ... }`)
whose body lets an exception escape.

## Example

`test_resources/async/test11.yr`:

```ymir
// An async never throws, it reports an error through the option it returns.

async check (x: i32)-> i32
    throws AssertError
{
    assert (x > 0);
    x
}
```

```text

```

## How to fix it

Return an option holding the error (`async check (x: i32)-> i32?`), and catch
the exceptions of the body inside the async.
