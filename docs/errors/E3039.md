# E3039

> only <> is resolved through the use of <>

where `<>` stands for a value the diagnostic fills in.

Raised from `DeclareErrorMessage::SINGLE_WILDCARD_USE` (`src/ymirc/semantic/declarator/errors.yr`),
by the check that runs once the whole package is validated.

## What it means

A path ending with `_` makes every submodule of the module it names visible at
once. When a single one of them turns out to be resolved through, the `use`
reaches much further than it needs to: every name the other modules declare
takes part in the resolutions of the scope, and can win one.

A `use` nothing at all is resolved through is reported as [E3038](E3038.md)
instead.

## Example

`test_resources/warnings/test6.yr`, where `group` holds `first` and `second`:

```ymir
in test6;

pub mod ::group;

use test6::group::_;

fn main () {
    firstValue ();
}
```

```text
Warning[E3039] : only test6::group::first is resolved through the use of test6::group::_
 --> test_resources/warnings/test6.yr:(7,19)
 7  ┃ use test6::group::_;
    ╋                   ^  note: name it on its own, with use test6::group::first;
    ┗━━━━━━━
```

## How to fix it

Name the module the scope actually resolves through, as the note spells it out.
