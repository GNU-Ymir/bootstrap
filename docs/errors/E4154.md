# E4154

> <> is a lazy variable, and cannot be used as a lvalue

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::NOT_A_LVALUE_LAZY` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A lazy parameter or binding was used as an lvalue. It names a computation, not a
location: each read produces the value again in a fresh slot, so there is no
storage a write could persist to. A lazy global is not concerned -- its value is
stored inside the global itself -- and a mutable one can be assigned.

## Example

`test_resources/lazyness/test7.yr`:

```ymir
fn main () {
    let lazy dmut a = lazy copy [1, 2, 3];

    a = copy [1, 2, 3];
    a = lazy copy [2, 3, 4];
}
```

```text
Error[E4154] : a is a lazy variable, and cannot be used as a lvalue
 --> test_resources/lazyness/test7.yr:(4,5)
 4  ┃     a = copy [1, 2, 3];
    ╋     ^ ^
    ┗━━━━━━━
```

## How to fix it

Bind the lazy value to an ordinary variable first.
