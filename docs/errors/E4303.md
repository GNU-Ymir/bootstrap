# E4303

> the filter of the list comprehension, constructed from type <>, must be determinable at compile time

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::LIST_COMPR_FILTER_CTE` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A comprehension written between parentheses constructs a tuple, and a tuple has
an arity fixed at compile time. Its iteration is unrolled during validation, so
the filter choosing which elements the tuple holds is computed there too, and a
test that is not a compile time value leaves the arity unknown.

What a filter can test therefore depends on what the iteration makes available
at compile time:

- over a range, the value of the iteration is a literal, so it can be tested,
- over a tuple, both the index and the element are, so both can be tested,
- over a slice or an array, only the index is: the elements live in memory the
  comprehension does not read at compile time.

A comprehension written between brackets escapes the constraint only when its
iteration is not unrolled: it then builds a slice at run time, where the filter
is an ordinary test -- see [E4302](E4302.md). Over a tuple it builds an array
whose length is fixed at compile time, so the filter is computed at compile time
there as well, and this error is raised on that form too.

## Example

`test_resources/diagnostics/test147.yr`:

```ymir
fn main (args: [[c8]]) {
    let n = args.len;
    let _ = (i for i in 0 .. 5 if i != n,);
}
```

```text
Error[E4303] : the filter of the list comprehension, constructed from type (..i32), must be determinable at compile time
 --> test_resources/diagnostics/test147.yr:(3,37)
 3  ┃     let _ = (i for i in 0 .. 5 if i != n,);
    ╋                                     ^^  error: value of type bool is needed but unknown at compilation time
    ┃
    = when validating test147::main -- (test_resources/diagnostics/test147.yr:(1,4))
    ┗━━━━━━━
```

## How to fix it

Test something the comprehension knows at compile time, or iterate something
whose length is not fixed at compile time, so that the result is a slice built
at run time:

```ymir
let _ = copy [i for i in 0 .. 5 if i != n];
```
