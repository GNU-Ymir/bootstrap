# E4312

> union <> has no method named <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::UNION_NO_METHOD` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A union holds one of its members, which one being known only at runtime, so a
method call on it has to be dispatched whichever member it holds. What it
answers to is therefore not the union of the methods of its members but their
intersection: a method every member declares publicly, under the same name and
with the same signature, the return type included. A union declaring a base
answers to the public methods of that base instead, every member descending
from it.

An operator applied to a union is such a call too, and the method it names is
the one reported: `u [i]` calls `opIndex`, `u [i] = v` calls `opIndexAssign`,
`u == v` calls `opEquals`, and `u < v` calls `opCmp`.

The notes name, member by member, what each declares under that name: the
prototype it declares, that it declares none, or that the one it declares is
private. Comparing them shows which member keeps the method out of the union.

## Example

`test_resources/type_union/test23.yr`:

```ymir
class A {
    pub self () {}
    pub fn foo (self)-> i32 { 1 }
}

class B {
    pub self () {}
}

union U
| A
| B;

fn bar (u : &U)-> i32 {
    u.foo ()
}
```

```text

    ╋       ^^^

 5  ┃     pub fn foo (self)-> i32 { 1 }
    ╋            ---  note: the member test23::A declares test23::A::foo ()-> i32
   ...
14  ┃ | B;
    ╋   -  note: the member test23::B declares no method named foo

```

## How to fix it

Declare the method in every member, publicly and with the same signature, or
reach the member through a match and call it there.
