# E4023

> colliding function definitions <> and <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::COLLIDING_FUNCTION_DEFINITION` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

Two functions have the same name and signatures that overload resolution cannot
tell apart, so a call naming them would be ambiguous.

## Example

`test_resources/function/test15.yr`:

```ymir
fn foo () {}
fn foo () {}

fn bar (i : i32) {i;}
fn bar () {}


fn baz (i : i32, j : i32) { i; j; }
fn baz (i : i32, ref j : i32) {
    i; j;
}
```

```text
Error[E4023] : colliding function definitions test15::foo ()-> void and test15::foo ()-> void
 --> test_resources/function/test15.yr:(1,4)
 1  ┃ fn foo () {}
    ╋    ^^^
   ...
 --> test_resources/function/test15.yr:(2,4)
 2  ┃ fn foo () {}
    ╋    ^^^
    ┗━━━━━━━
```

## How to fix it

Rename one of them, or change the parameters so the two differ in a way a
call can select on.
