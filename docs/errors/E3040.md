# E3040

> macro rule <> cannot be restricted to a list of values, only a built-in rule can be

where `<>` stands for a value the diagnostic fills in.

Raised during **declaration**, from `DeclareErrorMessage::MACRO_NOT_RESTRICTABLE` (`src/ymirc/semantic/declarator/errors.yr`).

## What it means

A rule can be restricted to a list of values, written `__key["null" | "in"]`, and the
list is compared against the content the rule consumed. A rule the macro declares
answers its rewritten body rather than that content, so a list cannot restrict it.

The rule head says so on its own, without a call, so the check runs when the macro is
declared.

## Example

`test_resources/lit_macro/test43.yr`:

```ymir
/*
 * A list of values restricting a rule of the macro, which answers its
 * rewritten body and not the content it consumed
 */

macro named {
    self (v=entry["a"]) skips (" ") #{
        #(v)
    }

    fn entry (i=__ident) skips (" ") #{
        12
    }
}

fn foo ()-> i32 {
    named#{ a }
}
```

```text
Error[E3040] : macro rule entry cannot be restricted to a list of values, only a built-in rule can be
 --> test_resources/lit_macro/test43.yr:(7,13)
 7  ┃     self (v=entry["a"]) skips (" ") #{
    ╋             ^^^^^
 --> test_resources/lit_macro/test43.yr:(11,8)
11  ┃     fn entry (i=__ident) skips (" ") #{
    ╋        -----  note: declared here
    ┗━━━━━━━
```

## How to fix it

Restrict the built-in rule inside the rule that names it -- `fn entry (i=__ident["a"])`
-- or split the accepted values into one rule each and choose between them with `|`,
which is ordered and selects the first that matches.
