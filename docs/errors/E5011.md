# E5011

> slice access always overflows, <> (len) <> <> (index)

where `<>` stands for a value the diagnostic fills in.

Raised during **lowering (YIL)**, from `OptimizerErrorMessage::ALWAYS_OVERFLOW` (`src/ymirc/lint/optimizer/errors.yr`),
by the bounds check pass of the optimizer.

## What it means

An access to a slice or an array is out of its bounds on every execution that
reaches it: the check guarding it is always taken, and the program panics
there.

The validator already rejects an index it can compute on a length it can
compute ([E4005](E4005.md)). This one is found later, on what the control flow
of the function says: the length of a mutable slice after the last assignment
to it, or the length a slice was given on every path leading to the access.
The optimizer only runs from `-O1`, so the diagnostic is never raised at `-O0`.

It is a warning: the access may sit on a path that never runs. Like any
warning, it only lets the compilation carry on in debug mode. The check and the
panic it guards are kept, so a program that reaches the access still panics
there.

## Example

`test_resources/warnings/test31.yr`:

```ymir
// an access the optimizer proves out of bounds warns, and panics as it did
fn foo ()-> i32 {
    let dmut a = copy [1, 2, 3];

    a [10]
}
```

```text
Warning[E5011] : slice access always overflows, 3 (len) <= 10 (index)
 --> test_resources/warnings/test31.yr:(5,7)
 5  ┃     a [10]
    ╋       ^--
    ┗━━━━━━━
```

## How to fix it

Correct the index, or the length the slice is given before it is read.
