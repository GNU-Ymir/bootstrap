# E5012

> a nogc function cannot allocate on the GC heap, the runtime call <> does

where `<>` stands for a value the diagnostic fills in.

Raised during **lowering (YIL)**, from `LoweringErrorMessage::NOGC_ALLOCATION` (`src/ymirc/lint/lowering/errors.yr`),
by the check of the frames of the `@nogc` functions.

## What it means

A function marked `@nogc` never allocates on the heap of the garbage
collector. Many constructs do, without spelling it out: a `copy`, a closure
capturing its environment, a concatenation, a map, a lazy value, a thrown
exception, a generator. They are found on the intermediate language the
function is expanded to, before any optimization, so that the answer does not
depend on the optimization level: the diagnostic names the runtime call the
construct expands to.

## Example

`test_resources/nogc/test3.yr`:

```ymir
// a @nogc function cannot allocate a slice on the GC heap (the empty .yil golden makes the case reach the lowering stage)

in test3;

@nogc
pub fn foo ()-> [i32] {
    copy [1, 2, 3]
}
```

```text
Error[E5012] : a nogc function cannot allocate on the GC heap, the runtime call _yrt_dup_slice does
 --> test_resources/nogc/test3.yr:(7,5)
 7  ┃     copy [1, 2, 3]
    ╋     ^^^^
    ┃
    = when lowering this nogc function -- (test_resources/nogc/test3.yr:(6,5))
    ┗━━━━━━━
```

## How to fix it

Work on records and on memory obtained from the C allocator (`malloc`, `mmap`)
instead, or move the allocation out of the `@nogc` function.
