# E4369

> the sites of tag <> on <> hold their arguments in different records, <> and <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::TAG_SITES_RECORDS` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

The value of a site is an instance of the record of its tag, a field per
parameter. A tag declaring template parameters, `tag ren {N: usize} (names: [[c8] ; N])`,
has one such record per binding of them, so two sites inferring different
template arguments hold their arguments in different records, which
`__pragma!tags` and `__pragma!field_tags` cannot put in a single array.

## Example

`test_resources/tag/test105.yr`:

```ymir
// The sites of a tag declaring template parameters read by __pragma!tags share an instance of its record

in test105;

tag ren {N: usize} (names: [[c8] ; N]) {}

#[ren (["a"]), ren (["b", "c"])]
fn foo () {}

#[ren (["a"]), ren (["b"])]
fn bar () {}

fn main () {
    let _bar_ = __pragma!tags (bar, ren);
    let _foo_ = __pragma!tags (foo, ren);
}
```

```text
 --> test_resources/tag/test105.yr:(15,17)
15  ┃     let _foo_ = __pragma!tags (foo, ren);

    ┗━━━━━━━
```

## How to fix it

Give the sites the same template arguments, or read them one by one, each with
a tag of its own.
