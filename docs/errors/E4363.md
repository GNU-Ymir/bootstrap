# E4363

> shift count <> is out of range for type <>, it must be in [0, <>)

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::SHIFT_OUT_OF_RANGE` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A shift `<<` or `>>` the compiler could compute has a count that is negative, or
not smaller than the width in bits of the shifted type. The generated code gives
such a shift no defined result, so the compiler refuses to fold it.

## Example

`test_resources/cte/test10.yr`:

```ymir
fn left () {
    cte assert ((1u32 << 32u32) == 0u32);
}
```

```text
Error[E4363] : shift count 32 is out of range for type u32, it must be in [0, 32)
 --> test_resources/cte/test10.yr:(5,23)
 5  ┃     cte assert ((1u32 << 32u32) == 0u32);
    ╋                       ^^
    ┃
    = when validating test10::left -- (test_resources/cte/test10.yr:(4,4))
    ┗━━━━━━━
```

## How to fix it

Shift by a count in the width of the type, or widen the shifted value first,
`cast!u64 (1u32) << 32u64`.
