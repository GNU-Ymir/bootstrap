# E4290

> none of the symbols <> can be used as a value

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::UNUSABLE_SYMBOLS` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A name designates several symbols, and each of them was rejected as a value -- a
type, a trait, a method referenced without an instance. The reason each was
rejected is listed under the diagnostic.

## Example

`test_resources/diagnostics/test142.yr`:

```ymir
// two imported traits of the same name, used as a value
mod a;
mod b;

use test142::a;
use test142::b;

fn main () {
    let _ = T;
}
```

```text
Error[E4290] : none of the symbols test142::a::T, test142::b::T can be used as a value
 --> test_resources/diagnostics/test142.yr:(9,13)
 9  ┃     let _ = T;
    ╋             ^  error: expression produces the type test142::a::T, but is used as a value
    ┃             ┗━ error: expression produces the type test142::b::T, but is used as a value
    ┃
    = when validating test142::main -- (test_resources/diagnostics/test142.yr:(8,4))
    ┗━━━━━━━
```

## How to fix it

Fix the use according to the reason given for the symbol that was meant, and
qualify it by its module (`a::T`) when the others are not.
