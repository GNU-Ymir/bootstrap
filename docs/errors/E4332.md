# E4332

> tag <> does not apply to <> <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::TAG_NOT_APPLICABLE` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A tag site, `#[tag (args)] decl`, merges the `apply` overload of the tag
into the declaration, and runs its `self` overload once for the site. The
overload is the one whose first template parameter receives the tagged
declaration: `{F: fn (T)-> R}` a function, `{class C}` a class, `{record R}` a
record, `{enum E}` an enum, `{union U}` a union. A `self` taking no template
parameter applies to any declaration, and a tag without `apply` overload only
registers the declarations it is put on.

A generator or an async reaches the overload typed with its handle, `yield gen
(n: i32)-> i32` as `fn (i32)-> yield-> i32` and `async twice (n: i32)-> i32` as
`fn (i32)-> async-> i32`, so that an overload typed `fn (i32)-> i32` does not
receive it. The keyword in front of `apply` (`fn`, `yield` or `async`) gives the
kind of the merged function, and names the candidate in the diagnostic.

The tag declares `apply` or `self` overloads, but none of them receives the
tagged declaration. Each one is listed as a candidate, with the reason it was
rejected: its first template parameter does not receive the declaration, or it
receives it but is not declared with its kind ([E4333](E4333.md)).

Two overloads receiving the declaration equally well are ambiguous, reported as
[E4280](E4280.md).

## Example

`test_resources/tag/test23.yr`:

```ymir
// no apply overload of the tag receives a record

tag a {
    pub fn apply {F: fn ()-> i32} ()-> i32 { F () }

    pub class apply {class C} {}
}

#[a]
record Foo {}

fn main () {}
```

```text

    ╋   ^

```

## How to fix it

Add to the tag an overload receiving the declaration, or remove the tag site
from the declaration it does not apply to.
