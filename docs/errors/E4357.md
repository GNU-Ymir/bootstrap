# E4357

> <> is an overload set, __pragma <> reflects over a single function

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::PRAGMA_OVERLOAD_SET` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

`__pragma!parameter_type` and `__pragma!return_type` describe the signature of one
function. A name declaring
several functions has several signatures, and the pragma cannot tell which one is
meant: the candidates are listed in the notes. `__pragma!is_function` is the only
function pragma accepting an overload set.

## Example

`test_resources/pragma/test30.yr`:

```ymir
fn over (x: i32)-> i32 { x }
fn over (x: f64)-> f64 { x }

fn main () {
    let _a_: __pragma!return_type (over) = 1;
}
```

## How to fix it

Give a single function: rename one of the overloads, or take the address of the
one that is meant through a typed variable (`let f: fn (i32)-> i32 = &over;`) and
reflect over `f`, whose parameters then have no name.
