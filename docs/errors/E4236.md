# E4236

> undefined template call for <> with <>

where `<>` stands for a value the diagnostic fills in.

Raised during **validation**, from `ValidateErrorMessage::UNDEFINED_TEMPLATE_CALL` (`src/ymirc/semantic/validator/errors.yr`).

## What it means

A template was called and no specialization of it accepts the arguments. Both
the template and the arguments are in the message, and the specializations tried
are listed under it.

## Example

`test_resources/templates/explicit/test4.yr`:

```ymir
fn foo {T : fn (i32)-> i32} (){}

fn main () {
    foo!{|x| => x + 1.0f} ();
    foo!{|x : f32| => x} ();
}
```

## Notes

The reason a specialization was refused is reported under this diagnostic, as a
note carrying no code of its own:

- `closure functions cannot be used as template values` (formerly E4022): a value was given for a template parameter of delegate type.
- `<> is not an array type` (formerly E4148): a `T of [U ; N]` parameter was given a type that is not a static array.
- `<> is not a map type` (formerly E4158): a `T of [K => V]` parameter was given a type that is not a map.
- `<> is not a record type` (formerly E4159): a `record T` parameter was given a type that is not a record.
- `<> is not a slice type` (formerly E4160): a `T of [U]` parameter was given a type that is not a slice.
- `<> is not an entity type` (formerly E4161): an `entity T` parameter was given a type that is not an entity.
- `template validation is not complete, unresolved: {<>}` (formerly E4201): more template arguments were given than the template has parameters.
- `template specialization expected a value not the type <>` (formerly E4274): a type was given for a value parameter such as `N : i32`.
- `the test of the template specialization failed` (formerly E4204): the `if` guard of the template evaluated to false.
- `attribute <> is not usable in this context` (formerly E4221): the template carries an attribute its instantiation does not accept, such as `@abstract` on a template function.

When the template arguments are inferred from a call rather than written, the
same notes are listed under the candidates of [E4226](E4226.md).

## How to fix it

Read the listed failures: each says why one specialization did not apply.
